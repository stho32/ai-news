Build once, run on any agent: A practical guide to agent skills
12.11.2026
Agent Skills sind versionierte Verzeichnisse mit einer SKILL.md als Kern, die eine wiederkehrende Aufgabe mit Eingabe, Ausgabe und Auslösebedingung beschreiben, aber keine Berechtigungen mitbringen: Der Host muss Tools, Credentials und Permissions bereitstellen, weshalb projekt- und team-spezifische Angaben wie Schema-, Store- und Engine-Namen in einem Manifest (im Data-Forge-Beispiel DuckDB lokal, Databricks oder DuckDB über einen Adapter) statt in der Skill-Definition liegen. Im Data-Forge-Demo koordinieren forge-init, forge-builder, forge-dbx und forge-lint eine Metrik-Pipeline über sieben Phasen mit menschlichem Checkpoint pro Phase und einem Pull Request aus Pipeline-Code, Schema-Änderungen und Tests; der Proof Agent lässt KI-generierte Änderungen von einem unabhängigen Verifier prüfen, der PASS, FAIL oder PARTIAL mit Belegen aus den geänderten Dateien liefert, wobei die GitHub Action nur den Diff statisch prüft, keine Tests ausführt und im Demo mit block-on-fail: false nur Hinweise gibt. Für Multi-Client-Betrieb dient skills/*/SKILL.md als Quelle, aus der ein Skript per node scripts/package.mjs --check die Client-Dateien .claude-plugin/plugin.json (Claude Code), .cursor-plugin/plugin.json (Cursor) und .github/agents/*.agent.md (GitHub Copilot) erzeugt. Als Grenze nennt der Beitrag Workflows mit stabiler Schnittstelle, Shared State, Audit Trail, langlaufender Kontrolle oder außerhalb des Modells erzwungenen Rechten, für die eine Anwendung die bessere Wahl ist; die vorgestellten Praktiken stammen aus einer Session auf der GitHub Universe 2026 mit Shishir Tewari von Procore.

Product Introducing Devin Apps
13.11.2026
Devin Apps sind private Web-Applikationen, die direkt auf Devins Cloud-Maschine gehostet werden und aus einer Beschreibung heraus entstehen; die App taucht sofort mit ihrer URL auf der Apps-Seite auf und durchläuft den Status Building, bis die erste Version live ist. Weil sie auf Devins Rechner laufen, greifen sie auf vorhandene MCPs, Integrationen und die Codebase zu — jeder Stack, der HTTP auf einem Port ausliefert, ist zulässig, ebenso SQLite oder Postgres auf derselben Maschine sowie Aufrufe der Devin API, um eigene Tools auf Devin aufzusetzen. Der Zugriff erfordert immer einen Devin-Login, Apps sind nie öffentlich, und die Freigabe lässt sich auf einzelne Personen, die Organisation oder das gesamte Enterprise begrenzen. Die URL bleibt über Versionen stabil; Änderungen laufen über „Edit in session" oder automatisiert per Datenabruf im Zeitplan bzw. Redeploy bei Branch-Änderungen, alle Stände erscheinen unter Deployments, und startet eine neue Version nicht, bedient weiterhin die vorherige. Technische Grundlage sind Memory-Snapshots: Die Maschine schläft ohne Nutzung und wacht beim Öffnen auf, was beim ersten Laden einige Sekunden kosten kann, wobei die Abrechnung an die Wachzeit gekoppelt ist. Eine App läuft auf einer Maschine und ist damit für interne Tools, Dashboards sowie Beta- und Staging-Umgebungen geeignet, nicht für hochfrequentierte Produktionsdienste.

Gemini 4 Carbon is now available in Devin
10.11.2026
Gemini 4 Carbon steht ab sofort in Devin Desktop und Devin CLI zur Verfuegung. Auf dem FrontierCode-2.0-Benchmark, der Modelle anhand realer Engineering-Aufgaben nach Qualitaet und Mergeability bewertet, erreicht das Modell 40,0 Prozent und liegt damit deutlich vor Gemini 4 Argon mit 26,3 Prozent sowie knapp vor GPT-6.1 Sol mit 39,0 Prozent. Der Zugewinn geht mit geringeren Kosten einher: Bereits bei niedrigem Reasoning-Aufwand uebertrifft Gemini 4 Carbon das Bestresultat von Argon, waehrend der Spitzenwert pro Task weniger als zwei Drittel des Argon-Aufwands kostet.
